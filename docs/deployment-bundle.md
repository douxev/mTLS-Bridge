# mTLS Bridge deployment bundle

A file format an IT admin can generate to distribute one (or several) mTLS
configurations to employees. The employee opens the file, enters the
passphrase once, and every config is immediately operational.

## Format

It is a **standard zip**. Extension convention: `.zip` (or `.mtlsw` if you
want a dedicated icon). Contents:

```
mtls-bridge-bundle.zip
├── README.txt              # optional, generated by default
├── configs.json            # manifest (schema v2)
├── <id1>-cert.pem          # client certificate chain
├── <id1>-ca.pem            # pinned upstream CA
├── <id1>.p12               # encrypted PKCS#12 (key + cert)
├── <id2>-cert.pem
├── <id2>-ca.pem
└── <id2>.p12
```

## `configs.json`

```json
{
  "schema": 2,
  "exportedAtMs": 1717000000000,
  "configs": [
    {
      "id": "jellyfin-paris-2026",
      "displayName": "Jellyfin (Paris)",
      "targetPackage": "org.jellyfin.mobile",
      "upstreamHost": "media.example.com",
      "upstreamPort": 443,
      "sni": null,
      "keystoreAlias": "mtls_bridge-jellyfin-paris-2026",
      "mode": "LOOPBACK",
      "syntheticIp": null,
      "syntheticPort": null,
      "loopbackPort": 23817,
      "enabled": true,
      "certPemFile": "jellyfin-paris-2026-cert.pem",
      "caPemFile": "jellyfin-paris-2026-ca.pem",
      "p12File": "jellyfin-paris-2026.p12",
      "pathToken": "Kx7P2mNqRtVy"
    }
  ]
}
```

Notes:
- `id`: stable identifier of the config (slug or UUID). Used as the routing
  key in the wrapper and as the Keystore alias (`keystoreAlias`).
- `mode`: `"LOOPBACK"` or `"VPN"`.
- `loopbackPort`: fixed port the proxy listens on (`127.0.0.1`), drawn in
  `10001..32767`. It is part of the URL pasted into the target app. On
  import, a port that is absent, outside `1..65535` (`0` included) or
  already taken by another loopback config is replaced by a port drawn in
  that range.
- `pathToken`: loopback only, recommended. The proxy only accepts requests
  whose path starts with `/<pathToken>/` (or that carry the session cookie
  set in the response), and strips that prefix before forwarding upstream.
  Absent = no check. Every rejection is logged (`REJECTED_TOKEN`), without
  the token or the path.
- `syntheticIp` / `syntheticPort`: VPN only (TEST-NET, e.g.
  `192.0.2.X:5001`).
- `p12File` is **optional**. Without it, the config is imported in "backup"
  mode and the employee has to provide their .p12 again manually.
- All `.p12` files in the bundle must share the **same passphrase**
  (deployment convention).

## Generation script (bash + openssl)

Short version, loopback mode only, reproduced as is in the app's help screen
(`DeploymentScript.kt`). The full generator
(`deployment-tools/bundle-generator.sh`) adds VPN mode, SNI, the validity
period and validation of every parameter.

```bash
#!/usr/bin/env bash
# Bundle generator for mTLS Bridge: short version, loopback mode.
# Full version (VPN mode, SNI, parameter validation):
# deployment-tools/bundle-generator.sh. Format: docs/deployment-bundle.md
set -euo pipefail

: "${USER:=$(id -un)}"            # missing in some containers

# === To be adapted by the admin ====================
CONFIG_ID="jellyfin-$USER"        # [A-Za-z0-9._-]: zip file name
DISPLAY_NAME="Jellyfin"
TARGET_PKG="org.jellyfin.mobile"
UPSTREAM_HOST="media.example.com"
UPSTREAM_PORT=443
BACKEND_CA_CRT="backend-ca.crt"   # CA that signs the client certs
BACKEND_CA_KEY="backend-ca.key"
# ===================================================

[[ $CONFIG_ID =~ ^[A-Za-z0-9][A-Za-z0-9._-]*$ ]] || { echo "invalid CONFIG_ID" >&2; exit 1; }
[[ $UPSTREAM_PORT =~ ^[1-9][0-9]{0,4}$ ]] && (( UPSTREAM_PORT <= 65535 )) \
  || { echo "invalid UPSTREAM_PORT" >&2; exit 1; }

# Fixed loopback port, drawn from 10001..32767 like the app does: the URL
# pasted into the target app stays valid when the proxy restarts.
LOOPBACK_PORT=$(( 10001 + ((RANDOM << 15) | RANDOM) % 22767 ))

# Path token (enabled by default): isolates the proxy from the other apps on
# the phone. 12 characters, same alphabet as the app (no 0/O nor 1/l/I).
gen_path_token() {
  local alphabet='ABCDEFGHJKMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz23456789'
  local out='' b
  while (( ${#out} < 12 )); do
    for b in $(od -An -N32 -tu1 /dev/urandom); do
      (( b < 216 )) && out+=${alphabet:b%54:1}
      (( ${#out} == 12 )) && break
    done
  done
  printf '%s' "$out"
}
PATH_TOKEN="$(gen_path_token)"

# JSON string: quotes, backslashes and control characters escaped.
json_str() {
  local s=$1 out='' c i
  for (( i = 0; i < ${#s}; i++ )); do
    c=${s:i:1}
    case $c in
      '"')         out+='\"' ;;
      '\')         out+='\\' ;;
      [[:cntrl:]]) printf -v c '\\u%04x' "'$c"; out+=$c ;;
      *)           out+=$c ;;
    esac
  done
  printf '"%s"' "$out"
}

P12_PASSPHRASE="$(openssl rand -base64 32)"   # to be sent out of band
WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT
BUNDLE="$WORK/bundle"                          # zip contents, nothing else
mkdir "$BUNDLE"

# Client key + signature by the backend CA
openssl req -new -newkey rsa:3072 -nodes \
  -keyout "$WORK/client.key" -out "$WORK/client.csr" \
  -subj "/CN=$USER" 2>/dev/null
openssl x509 -req -in "$WORK/client.csr" \
  -CA "$BACKEND_CA_CRT" -CAkey "$BACKEND_CA_KEY" -CAcreateserial \
  -days 365 -out "$BUNDLE/$CONFIG_ID-cert.pem" 2>/dev/null
cp "$BACKEND_CA_CRT" "$BUNDLE/$CONFIG_ID-ca.pem"

# PKCS#12: passphrase passed through openssl's environment only (env:),
# never as an argument (readable by everyone via ps / /proc/<pid>/cmdline).
P12_PASSPHRASE="$P12_PASSPHRASE" openssl pkcs12 -export \
  -in "$BUNDLE/$CONFIG_ID-cert.pem" -inkey "$WORK/client.key" \
  -out "$BUNDLE/$CONFIG_ID.p12" -passout env:P12_PASSPHRASE
rm -f "$WORK/client.key" "$WORK/client.csr"   # plaintext key

# Manifest (schema v2)
cat > "$BUNDLE/configs.json" <<EOF
{
  "schema": 2,
  "exportedAtMs": $(date +%s)000,
  "configs": [{
    "id": $(json_str "$CONFIG_ID"),
    "displayName": $(json_str "$DISPLAY_NAME"),
    "targetPackage": $(json_str "$TARGET_PKG"),
    "upstreamHost": $(json_str "$UPSTREAM_HOST"),
    "upstreamPort": $UPSTREAM_PORT,
    "sni": null,
    "keystoreAlias": $(json_str "mtls_bridge-$CONFIG_ID"),
    "mode": "LOOPBACK",
    "syntheticIp": null,
    "syntheticPort": null,
    "loopbackPort": $LOOPBACK_PORT,
    "enabled": true,
    "certPemFile": $(json_str "$CONFIG_ID-cert.pem"),
    "caPemFile": $(json_str "$CONFIG_ID-ca.pem"),
    "p12File": $(json_str "$CONFIG_ID.p12"),
    "pathToken": $(json_str "$PATH_TOKEN")
  }]
}
EOF

# Final zip: entries at the root, without the uid/gid of the admin's machine.
zip -q -j -X "$WORK/bundle.zip" "$BUNDLE"/*
mv -f "$WORK/bundle.zip" ./mtls-bridge-bundle.zip

echo "Bundle ready: ./mtls-bridge-bundle.zip"
echo "Passphrase to send out of band: $P12_PASSPHRASE"
echo "URL to paste into the target app: http://127.0.0.1:$LOOPBACK_PORT/$PATH_TOKEN/"
```

## Distribution

- Email with the zip + the passphrase over a SEPARATE channel (Signal,
  Matrix…).
- MDM (Intune, Jamf): push the file + an environment variable for the
  passphrase.
- QR code for the passphrase, scanned in the app at import time.

## Employee side

1. Install mTLS Bridge from the Play Store (or the provided enterprise
   channel).
2. Open the received .zip.
3. The app opens, offers to import it, asks for the passphrase and imports
   everything.
4. Start Jellyfin and set the server URL shown by mTLS Bridge (for example
   `http://127.0.0.1:23817/Kx7P2mNqRtVy/`, shown in the config details).

## Security

- The `.p12` is encrypted by PKCS#12 (AES-256 with a recent openssl). The
  passphrase must never be in the same file or on the same channel as the
  bundle.
- After import into the Keystore, the key becomes non-exportable from the
  device (TEE/StrongBox when available). The original .p12 can be erased.
- The "delete after import" option in the UI does this automatically
  through `ContentResolver.delete()` (best effort, depending on the
  provider).
